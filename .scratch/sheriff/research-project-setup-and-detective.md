## Summary

- The article is a menu: ESLint, Sheriff, Detective, Prettier + organize-imports, Conventional Commits + commitlint, Husky, Testing Library, monorepo/Nx, Native Federation. This repo already has ESLint, Sheriff (with dependency rules), Prettier, Testing Library (ADR 0004) and CI gating. Missing: commitlint, git hooks, import sorting, Detective.
- Nx, the monorepo split and Native Federation don't fit a single-app Template. Skip them.
- **Commit messages:** all 72 commits use the Conventional Commits shape, but stock `@commitlint/config-conventional` rejects 11 of them on `subject-case`: 8 Dependabot "Bump …" subjects and 3 agent subjects that start with a proper noun. A commitlint check in CI is cheap and useful, but only with `subject-case` turned off.
- **Git hooks (Husky):** low value here. CI already runs lint and the format check on every PR, `ng lint` takes about 2 s, and Husky writes `core.hooksPath` into the repo's git config, which this shared checkout has been burned by before (`CLAUDE.local.md`).
- **organize-imports:** optional. It removes unused imports (destructive) and overrides Prettier's TS parser. Low value now that typescript-eslint flags unused imports.
- **Detective** (MIT, v2.1.2, released 2026-06-06) is a local web UI plus an MCP server. It shows the static module graph (through Sheriff's `getProjectData`), change coupling, hotspots (commits × McCabe), team alignment, trend analysis and per-file "x-ray". It doesn't use Sheriff's tags or `depRules`, so it can't show rule violations.
- **Verified incompatibility:** Detective 2.1.2 pins `@softarc/sheriff-core` 0.17.3. That version can't parse this repo's `sheriff.config.ts` (`modules` + `autoTagging: false`), so the dependency graph and structural coupling views fail. The git-history analyses still work.
- **Verified:** run through plain `npx` from a clean directory, Detective pulls TypeScript 7.0.2 and crashes with `ts.readConfigFile is not a function`. It must resolve the project's TypeScript 6.0.
- With 72 commits in 17 days, one human author name ("agent") and one Feature, Detective's output is mostly noise for now. It becomes useful in projects created from the Template, after months of history.
- **Sheriff follow-up found:** since 0.18.1, `encapsulationPattern` accepts a regex, which confirms the article's "future" claim. That gives ticket `02-encapsulation` an option besides `internal/` folders.

## Detective

**What it is.** "Visualize your TypeScript project" ([registry](https://registry.npmjs.org/@softarc/detective)). MIT. Author Manfred Steyer; maintainers Steyer, Rainer Hahnekamp and Auke van Oost. Latest **2.1.2** (2026-06-06), after 2.0.x (2025-09), 1.3.0 (2024-11) and 1.0.0 (2024-09). Repo [angular-architects/detective](https://github.com/angular-architects/detective); HEAD is `0184402` "feat: add --fill-cache switch" (2026-06-06). Maintenance is bursty: no release between 2025-09-30 and 2026-06-06. The repo declares `node >=20.17` ([package.json](https://github.com/angular-architects/detective/blob/main/package.json)); the published package declares no `engines` (registry). The tool's own UI is built with Angular 18 (repo `package.json`), which doesn't matter to users. Runtime deps include `@softarc/sheriff-core` **0.17.3 (exact)**, `express 4.21.0`, `@modelcontextprotocol/sdk 1.17.3` and `@jscpd/*` (registry). `typescript` is resolved as sheriff-core's peer (`>=4.8`).

**How it works** (verified from source at HEAD):
- **Entry and graph:** globs default entries (`src/main.ts`, `main.ts`, `projects/*/src/main.ts`, …, or Nx patterns if `nx.json` exists) and calls Sheriff's `getProjectData(entry, cwd)` for the file-level import graph ([deps.ts](https://github.com/angular-architects/detective/blob/main/apps/backend/src/infrastructure/deps.ts)). That covers only files reachable from `main.ts`: in a run on a copy, `src/app/testing` showed 0 files.
- **Scopes:** analyses group files by folder-prefix "scopes" saved in `.detective/config.json` (picked in the UI or written by hand). Sheriff's tags and `depRules` are carried in the model but not used by any analysis (grep of `apps/backend/src`).
- **Git:** runs `git log --numstat --pretty=format:"%an <%ae>,%ad%x09%H,%s"` and caches it in `.detective/log`, keyed by tree hash ([git.ts](https://github.com/angular-architects/detective/blob/main/apps/backend/src/infrastructure/git.ts), [log-cache.ts](https://github.com/angular-architects/detective/blob/main/apps/backend/src/services/log-cache.ts)).
- **Analyses** ([services/](https://github.com/angular-architects/detective/tree/main/apps/backend/src/services)):
  - structural coupling and cohesion between scopes;
  - **change coupling**: a scope × scope matrix counting commits that touch both, plus a sum of coupling;
  - **hotspots**: score = commits × complexity, where complexity is McCabe (TS AST branch count) or line count. Shown as a treemap with a percent-of-max slider;
  - **team alignment**: changed lines per scope by team or user, with `teams` and `aliases` in config;
  - **trend analysis** and **x-ray**: per-file metrics such as `any` types, magic numbers, feature envy, duplication via jscpd.
  - The [2024 forensics article](https://www.angulararchitects.io/en/blog/your-architecture-as-a-crime-scene-forensic-analysis-for-your-angular-solutions/) adds the "ex-team member" and time-window analyses, and warns that scores are for prioritizing, "not suitable as targets".
- **CLI** ([parse-options.ts](https://github.com/angular-architects/detective/blob/main/apps/backend/src/options/parse-options.ts)): `--port` (default 3334), `--path`, `--config` (default `.detective/config.json`), `--open false`, `--demo`, `--trend-analysis`, `--fill-cache`, `--mcp`.
  - `--mcp` runs a **stdio MCP server** with 14 tools (`coupling_get`, `changeCoupling_get`, `hotspots_find`, `xray_get`, …) and German instructions ([mcp/server.ts](https://github.com/angular-architects/detective/blob/main/apps/backend/src/mcp/server.ts)). An HTTP MCP endpoint is also mounted at `/mcp`. Neither is mentioned in the README.
- **Writes:** creates `.detective/` (`config.json`, `log`, `hash`, trend cache) in the git root ([config.ts](https://github.com/angular-architects/detective/blob/main/apps/backend/src/infrastructure/config.ts)). The log cache contains author names and emails.
- **Network:** `app.listen(port)` with no host. The local run showed it listening on `*:3399`, all interfaces, including `POST /api/config`, which writes the config file. Run it only on trusted networks.

**How to run here (safely, without touching the repo).** Use the project's TypeScript: install it next to the repo's `node_modules`, or run from a temp directory where TypeScript is pinned:
```sh
mkdir /tmp/det && cd /tmp/det && npm i --ignore-scripts @softarc/detective@2.1.2 typescript@~6.0.2
git clone <repo> /tmp/det/repo            # Detective writes .detective/ into the analysed repo
node node_modules/@softarc/detective/bin/main.js --path /tmp/det/repo --open false --port 3399
curl localhost:3399/api/cache/log/update  # fill the git log cache, then open the UI
```
The README's way is `npm i @softarc/detective -D && npx detective` ([README](https://github.com/angular-architects/detective#using)). If adopted in-repo, add `/.detective` to `.gitignore` and `.prettierignore`.

**What I ran** (all in `/tmp/det-run`, on a `git clone` of this checkout, nothing written to the repo):

2. With `typescript@~6.0.2` (Angular 22 requires `>=6.0 <6.1`, per the `@angular/compiler-cli` peers): it works with no `sheriff.config.ts` present (auto-tagged folders).

Renaming `modules:` to the legacy `tagging:` in the copy made it load. Detective falls back to "limited functionality": no module graph or structural coupling.
4. With scopes set to the 11 Sheriff module folders:
   - **Hotspots (McCabe):** `profile/edit-profile/edit-profile.ts` 108 (12 commits × complexity 9), `testing/fake-auth-session.ts` 72, `auth/credentials-form.ts` 35, `auth/auth-session.ts` 30, `pwa/update-prompt.ts` 30.
   - **Change coupling (commits touching both):** `features/notes`–`profile` 11, `auth`–`profile` 10, `profile`–`testing` 8, `auth`–`testing` 8, `live-data`–`profile` 7.

**What it'd reveal for this repo.** Little that's actionable yet. The history is 72 commits since 2026-10-01, and many are repo-wide refactors (renames, the move into `src/app/features`), which inflate change coupling. The top hotspot, `edit-profile.ts`, and the profile↔Feature co-changes are candidates to look at, not findings. Team alignment needs real authors. Value grows in a project created from the Template, with months of history and several Features: change coupling between `feature` scopes would flag hidden coupling that Sheriff's import rules can't see. The MCP mode could let agents query hotspots before refactoring. That's untested.

**Relation to Sheriff.**
- Complementary: Sheriff enforces import rules at lint time, while Detective shows structure plus history-based coupling, and only reads Sheriff's import graph.
- **Version conflict:** installing Detective as a devDependency nests sheriff-core 0.17.3 under it (fine for npm; the root keeps 0.20.0 for the ESLint plugin's exact peer), but that nested copy can't read our config.
- Dependabot's `other` group would update Detective, but the pin lives inside Detective's own `package.json`, so only a new Detective release fixes it.

## Recommendations (value ÷ effort, highest first)

1. **Record the commit convention in `AGENTS.md`.** Conventional Commits; the subject may start with a proper noun. Value: keeps agents consistent. Effort XS.
2. **Ticket 02-encapsulation: add `encapsulationPattern` as an option.** It accepts a string or RegExp in Sheriff ≥0.18.1, e.g. `/(^|\/)_/` for underscore-prefixed private files, so the triage can compare it with `internal/` folders. Both change the Feature shape in `docs/features.md`. Effort XS to note, M to implement.
3. **commitlint in CI** (`pr.yml` or a `checks.yml` job, `fetch-depth: 0`, `--from base.sha --to head.sha`). Config: extend `@commitlint/config-conventional`, set `subject-case` to `[0]` (otherwise Dependabot and proper-noun subjects fail, as measured), and keep `header-max-length 100`. Effort S. Value is moderate: the history is already compliant, so this mainly guards against drift. Node ≥22.12 is fine with `.nvmrc` 24.
4. **Detective, ad hoc only.** Run it occasionally from `/tmp` with TypeScript 6 pinned, as above. Don't add it as a devDependency while it pins sheriff-core 0.17.3. Re-check when a Detective release bumps sheriff-core to ≥0.18. Effort XS per run.
5. **Skip:** Husky/pre-commit (shared-checkout git-config risk, and CI already gates), pretty-quick, organize-imports (optional at most, non-destructive mode), path aliases, monorepo, Nx, Native Federation.
6. **Sheriff spec items the article confirms or touches:** `sheriff list` in PR evidence was done (PR #43). The article's `configs.all` matches. No change needed.
